# Decisions

- Sutra has its own git repo in this folder, because the enclosing repo is the home directory with an unrelated `aura` remote.
- Next.js is pinned to 15 because the brief's `next lint` was removed in Next 16.
- Tailwind is pinned to v3 for the shadcn config format in `components.json`; shadcn components are hand-copied, not installed via CLI.
- Later-phase libraries (Recharts, PapaParse, SheetJS, pdf-lib, qrcode, Anthropic, Swagger) are installed by the phase that first uses them.
- `npm run keys` trims `/rest/v1/` from `NEXT_PUBLIC_SUPABASE_URL`, because the client needs the bare project URL.
- Added tables the brief implies: `universities`, `scholarship_portals`, `alerts`, `notifications`, `webhook_deliveries`, `university_result_batches`, `rate_limits`, `audit_tamper_backup`.
- Added `ADMISSION_SURGE` to `cluster_type` for the 48-hour surge rule in Section 9.6.
- `consents` gains `approved_at`, `denied_at`, `consumed_at`, `otp_expires_at`; one-time view needs a consumed marker and OTPs need a 5-minute expiry.
- `scholarship_requests` gains `academic_year` and `denial_reason`, needed for duplicate-claim checks and the portal's denial message.
- `verifier_orgs` gains `scope`, so regulators can have broader per-org scope.
- Seat-matrix totals are enforced by `seat_matrix_valid()` called from code, not a table constraint, since rows are written one chunk at a time.
- Column-level grants hide `students.created_by_institution_id` from all logged-in users, so a second institution cannot learn who created a shared student.
- Sessions use httpOnly cookies, so all auth runs server-side; the browser Supabase client is for Realtime only.
- Realtime token handoff from the httpOnly session is built with the dashboards in Phase 4.
- MFA enrolment (`/settings/security`) and login rate limiting are built in Phase 6 with the other security pages.
- Sidebar items for later phases are shown but not linked until they are built.
- Seed volume is 2,313 students and 2,413 enrolments, above the brief's ~2,000 and ~2,200, because withdrawn and supernumerary rows sit on top of the 70-98% fill; accepted since no scenario depends on the total.
- Two students-per-enrolment sources exist: lateral UG entrants hold an earlier PassedOut diploma enrolment, so about 100 students have two records without creating false cross-matches.
- Programs carry academic year 2026-27 as the reporting cycle, while admission dates span 2024 (with Sem 1-4 results) and 2026 (freshers); intake counts all Active enrolments per program.
- Semester 0 in `university_results` holds qualifying marks.
- The brief says "3 orgs" but lists 4 verifiers; the seed creates the 4 listed.
- Two reporting gaps are planted: Thar College of Architecture and Sundarban College of Pharmacy have programs but no submissions, for the submission tracker.
- `messy_upload.csv` is 8 clean rows, 100 rows with 3 auto-fixable defects each, and 12 rows that need a person; applying all fixes admits more than the 8 rows in the scenario, which still fires OVER_INTAKE.
- Demo account emails use the reserved `sutra.example` domain, so they can never reach a real inbox.
- The seed stores the scholarship portal key in `.env.local` as well as printing it once, because the database holds only its hash and `/portal-demo` needs it.
- Re-running the seed resets seeded rows to their planted state; it leaves `audit_log` untouched because the log is append-only.
- Client-side mutations use route handlers under `/api/app`, not server actions, so one error shape and HTTP tests cover them.
- `npm run demo:reset` (uses a `seeded` flag) returns the data to its planted state between rehearsals; it never touches the audit log.
- `messy_upload.csv`'s first two rows take the free NRI and lateral seats (58 to 60); the next six fire OVER_INTAKE and OVER_QUOTA and are held back, so the meter turns red on the attempt rather than admitting past intake.
- Capacity rules only count rows with no other errors, so unfixed rows don't crowd the issue list; after "Apply all safe fixes" the rest then hit OVER_INTAKE.
- Name casing and spacing use FIELD_FORMAT at Warning severity with a safe fix; a `+91` mobile is treated as a format issue, not formula injection.
- Institutions can see only a generic CROSS_INST_DUP notice; alerts are readable only by AICTE.
- AI uses `claude-sonnet-4-6` as the brief specifies, only when `ANTHROPIC_API_KEY` is set; otherwise a keyword matcher and templates give the same safe behaviour. With no key set, the live AI path has not been exercised.
- Ask the Data sends the officer's typed question and catalog descriptions to Claude; summaries see only aggregate rows. Upload text and student data never enter a prompt.
- The category-spike check compares NRI share with peers in the same state, or nationally when a state has fewer than 3 peers.
- Fraud re-runs keep a cluster's review status, so a re-run never reopens a reviewed case.
- `GET /students/{apaarId}/verify` takes the consent ID as `X-Consent-Token`, and each consent works once.
- A scholarship poll must send `request_id`; a fresh application after a fulfilled one for the same scheme and year is a duplicate claim.
- The audit trail records sensitive reads and every write, but not each ordinary dashboard page view, to keep the chain meaningful.
- Four early audit entries (seq 446, 447, 501, 502) hold a synthetic APAAR ID in an API path, logged before the path was redacted. The log is append-only, so they stay; `npm run smoke` lists them on every run and fails on any new one.
- Public record lookups log an ID only if the record exists, so a mistyped APAAR ID never enters the audit log.
- Baseline and final e2e leave out over-intake submits on the shared database (rule 5); the `upload` and `scenarios` sections gain a preview-only mode, with `E2E_ALLOW_INTAKE_WRITES=1` to run the old behaviour on a private database.
- Vercel region is `bom1`, because the Supabase pooler host is `aws-0-ap-south-1` (Mumbai).
- AICTE aggregates are cached 30 seconds under one key for all AICTE roles, since those totals are the same for every AICTE user, and are cleared after uploads, alerts and record verification; open alerts are never cached.
- RLS policies were left unchanged, so slow pages gained explicit institution or university filters, and two plain counts use the admin client with an explicit owner filter.
- The Next 15 middleware still calls `getUser` on each request, because it refreshes the session; `cache()` removes only the repeats within rendering.
- `demo:reset` ran three times rather than once: twice as a clean starting point for the final checks and once at the very end, since tests that write data need it and the brief asks for the planted state at the finish.
- `clean_upload.csv` on B.Tech CSE cannot reach 0 blocking errors, because 12 rows do not fit in CSE's 2 free seats and rule 3 forbids changing validation or planted data. It has 0 eligibility errors there and 0 errors of any kind on ECE, which is what it was generated for.
- AI default checked 2026-11-01: `gemini-3.8-flash` is listed as stable with a free tier and shown in Google's OpenAI-compatible examples. It is set in `.env.example`.
- No Groq default is set: Groq's docs list `llama-3.1-8b-instant` as a production instant model but tag it Enterprise, and do not state free-plan availability, so `AI_MODEL` must be chosen from Groq's list.
- `AI_PROVIDER` must now be set to use AI, so an `ANTHROPIC_API_KEY` alone stays in offline mode, as the brief's default of `none` requires.
- A rate limit (429) falls back at once without the retry; timeouts, network errors and 5xx get the one retry.
- A failed model call stops further calls for that request or detection run, so an outage cannot stack up timeouts.
- `explained_by` on `fraud_clusters` records who wrote each explanation, for the fraud page label.
- Seeded credentials sign in `DEMO_PUBLIC_URL`, defaulting to the live demo, because `valid_credential.json` must not mention localhost. The Fake QR test button still changes the program field, since its on-screen text describes that.
